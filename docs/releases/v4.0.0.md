# v4.0.0 — Standalone Container

**Date:** 2026-11-02 (draft)

## Summary

A home-lab operator can run The Sommelier from a published image with only
env variables and volumes. The container needs no repo checkout, no
1Password, and no SSH access to Home Assistant.

## Upgrade from v3.x

v4.0.0 runs from a published image. Follow
[Upgrade from v3.x](https://github.com/unibrain1/TheSommelier/blob/main/docs/upgrade-from-v3.md). Breaking changes:

- Settings come from plain env variables. `op://` values no longer work (#109).
- Plan settings move to `holidays.yaml` and `evolution_tracks.yaml`. Convert `plan_config.py` (#111, #125).
- Home Assistant pulls two JSON files. The SSH push and `HA_SSH_TARGET` are gone (#113).
- `CLAUDE_ENABLED`, `DIGEST_ENABLED` and `COMMUNITY_NOTES_ENABLED` are gone. Settings alone turn each feature on (#126–#128).
- `HEALTHCHECK_URL` replaces the ping key, slug and base URL (#130).
- Set at most one Claude key (#131).

## Verification

After `docker compose up -d` (or `./compose.sh up` on production):

- `docker compose logs the-sommelier` shows a `Settings:` block, and each
  feature that you set up is `on`.
- The first sync ends with `==> Sync complete.`, and `docker inspect` shows
  the container `healthy`.
- The site loads. `plan.json` keeps its `changelogHistory` from before the
  upgrade.
- With `HEALTHCHECK_URL` set, the check gets a ping after the sync.
- With `HA_ENABLED=true`, `/thisweek.json` and `/today.json` return the
  current week, and the Home Assistant sensors show it after `rest.reload`.

Production passed each check on 2026-11-08 (#116).
