# v4.0.0 — Standalone Container

**Date:** 2026-11-02 (draft)

## Summary

A home-lab operator can run The Sommelier from a published image with only
env variables and volumes. The container needs no repo checkout, no
1Password, and no SSH access to Home Assistant.

## Deployment Instructions

- Settings (#109, #110): before production pulls `main` at the v4.0.0
  release, replace the `op://` values in `.env` with plain values. Then run
  `docker compose down && docker compose up -d`. A `restart` alone
  fails each run, because the running container keeps its old
  environment: the `op://` values, and no `DATA_DIR` and `SITE_DIR`.
- Plan settings (#111, #125): convert `scripts/plan_config.py` one time with
  `python3 scripts/convert_plan_config.py scripts/plan_config.py config`.
  It writes `config/holidays.yaml`, `config/evolution_tracks.yaml` or both,
  one for each setting that `plan_config.py` has. Then
  delete the old `config/plan.yaml` on the server. The sync does not use it
  and logs a warning. Without `holidays.yaml`, the plan uses the default
  holidays. Without `evolution_tracks.yaml`, the plan uses no evolution
  tracks. The plan step needs PyYAML. The image installs it at build time,
  so rebuild the image.
- Home Assistant (#113): the SSH push is gone. Set `HA_ENABLED=true` in
  `.env` (the default is off), then run
  `docker compose down && docker compose up -d`. Change the `resource` of
  each REST sensor to the site URL of `thisweek.json` and `today.json`.
  Remove `HA_SSH_TARGET` from `.env` and the `ha_ssh_key` mount from
  `docker-compose.override.yml`. Also remove the push key from
  `authorized_keys` and the `sudo` rule for `tee` on the Home Assistant
  host. The steps are in
  `docs/upgrade-from-v3.md`.
- Standalone image (#112): rebuild the image. On a host that uses
  `examples/compose.yaml`, copy the old `data/` caches into the
  `sommelier-data` volume. Production copies them to a host folder (#116).
  Convert `scripts/plan_config.py` into
  `./config`, as the Plan settings bullet above says.
- New hosts (#115): `examples/compose.yaml` runs the published image with no
  checkout. The README has the quick start. `docs/configuration.md` has the
  variable table, and `docs/upgrade-from-v3.md` has the steps to upgrade from
  v3.x.
- Production cutover runs on the `edge` image. This is a temporary
  exception until `4.0.0` exists. Each push to `milestone/v4.0.0` pushes
  the image (#114). A manual run is not possible before the release,
  because GitHub starts a manual run only when the workflow file is on
  `main`. After the release, change the image pin to `4.0.0` (#116).
- Production (#116): docker02 runs the image from the HomeLab stack
  `services/applications/the-sommelier/`, not from a checkout. Its
  `CLAUDE.md` has the commands and the rollback step. The data is in
  `/home/ansible/data/the-sommelier/data`, not in a named volume. One week
  after the cutover with no problems, remove the old checkout in
  `/home/ansible/container/the-sommelier` and the HA SSH push key.
- GHCR package (#114): the package is private until the release. On
  docker02, `./compose.sh up` logs in to GHCR with a token from 1Password,
  pulls, and logs out. At the release, after the `v4.0.0` tag push, set the
  package visibility to public in the package settings.
- Claude (#126, #131): remove `CLAUDE_ENABLED` from `.env`. Set at most
  one Claude key. An `ANTHROPIC_API_KEY` that your shell exports turns the
  notes on for `bash fetch.sh` and puts the runs on your API bill.
- Digest and community notes (#127, #128): remove `DIGEST_ENABLED` and
  `COMMUNITY_NOTES_ENABLED` from `.env`. The settings alone turn each
  feature on. A flag set to `false` no longer turns the feature off. To
  turn a feature off, remove its settings.
- Healthchecks.io (#130, #129): set `HEALTHCHECK_URL` to the full ping URL
  of the check in `.env`. Remove
  `HEALTHCHECK_PING_KEY`, `HEALTHCHECK_SLUG`, `HEALTHCHECK_BASE_URL` and
  `HEALTHCHECK_ENABLED`. The sync ignores them and logs no warning. Without
  `HEALTHCHECK_URL`, the ping stops and the check reports "down".
  Production has no `.env`: the HomeLab stack builds `HEALTHCHECK_URL` from
  the 1Password ping key (#116).
