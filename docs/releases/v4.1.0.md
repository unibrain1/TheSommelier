# v4.1.0 — Trustworthy Runs

**Date:** 2026-11-09


## Summary

A green Healthchecks ping now means a good run. A degraded run says so, and Claude gets only its own key.

## Issues Resolved

- [#143](https://github.com/unibrain1/TheSommelier/issues/143) — security: Claude gets only its own key, and the site sends security headers.
- [#142](https://github.com/unibrain1/TheSommelier/issues/142) — fix: The success ping counts warnings, and the fail ping names the failed step.
- [#108](https://github.com/unibrain1/TheSommelier/issues/108) — feat: A sync reuses the tasting note of an unchanged week, so Claude writes fewer notes.
- [#145](https://github.com/unibrain1/TheSommelier/issues/145) — chore: `send_digest.sh` reads `.env` unless both SMTP secrets are set, as `fetch.sh` does.
- [#148](https://github.com/unibrain1/TheSommelier/issues/148) — feat: The site footer and `/version.json` show the image version.

## Other fixes

- security: The digest email and `digest.html` escape each data value. Before, a tasting note could put HTML into them.

## Deployment

- Change the image tag from `4.0` to `4.1`. Then run `docker compose pull`, `docker compose down` and `docker compose up -d`. The scheduled sync and the first sync now run through `sync.sh`. No setting changes.
- A CellarTracker or calendar fetch that takes more than 5 minutes now fails the sync. The fail ping names the step `fetch`.
- `DIGEST_SEND_SCHEDULE` must fire after the first `SYNC_SCHEDULE` run of the day. If it fires before, the digest is stale and sends a fail ping each day. The defaults are safe.
- Remove `OP_SERVICE_ACCOUNT_TOKEN` from `.env`. The container now warns when it is set.
- Check `SYNC_SCHEDULE` and `DIGEST_SEND_SCHEDULE` before the update. The container does not start with a line break in either value.
- The container also does not start with a cron expression that is not valid. It does not start with more than one expression in `DIGEST_SEND_SCHEDULE`.
- Set `USERNAME` and `PASSWORD` as plain text. curl now URL-encodes them. A password that you encoded by hand, such as `p%26ss` for `p&ss`, no longer logs in.
- A control character in `USERNAME` or `PASSWORD` stops the run. A CRLF `.env` can cause this. Save it with LF line ends.
- Change an `http://` value in `GOOGLE_CALENDAR_ICS_URL` or `HEALTHCHECK_URL` to `https://`. Each sync logs a warning for `http://`, because the URL holds a secret.
- The success ping body has a `Warnings: N` line and lists each warning. A failed or stale digest send now sends a fail ping to `HEALTHCHECK_URL`. The next successful sync resets the check.
- The success ping also counts a menu enrichment that fails, and a previous plan that the sync cannot read.
- The site now sends a Content-Security-Policy. It allows only the site itself and Google Fonts. It blocks a script, style or image from another host.
- The site can no longer be shown in an iframe on another page, such as a Home Assistant dashboard.
- The first sync checks the menu enrichment cache again. It can call Claude again for some meals and log `WARNING: enrichment field` lines.

## Verification

- #142: After one sync, the success ping body has a `Warnings:` line. With no degraded step and no settings warning, it shows `Warnings: 0`.
- #108: With Claude on, run two syncs on the same day with no cellar change. The second log shows `Notes: 52 reused from the previous plan, 0 weeks have no note`.
- #143: After one sync, `plan.json` has tasting notes. With `https://` URLs and no `OP_SERVICE_ACCOUNT_TOKEN`, the log shows no new `WARNING` line.
